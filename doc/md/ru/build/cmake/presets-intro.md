# CMake-пресеты — модель и требования

Общий фон для руководств по IDE. Прочтите один раз, затем следуйте руководству
для [вашей IDE](README.md).

## Что такое эти пресеты

`CMakePresets.json` в корне репозитория поставляет матрицу пресетов **configure**,
**build** и **test**, ключом которых служит компилятор и целевая архитектура.
IDE и вспомогательные скрипты `script/ci`, выбравшие один и тот же пресет,
разделяют одно и то же дерево сборки — конфигурация в IDE и сборка из терминала
не конфликтуют за один каталог.

- Каждый пресет конфигурируется в своё дерево `build/<preset>/`, поэтому разные
  компиляторы и архитектуры не пересекаются.
- Артефакты складываются в `bin/<OS>-<Compiler>.<Version>-<arch>/<config>/`.
- Пресеты фильтруются по хост-ОС: Windows видит `clang-*`/`gcc-*`/`msvc-*`, Linux
  видит `clang-*`/`gcc-*` (+ `osxcross-*`), macOS видит `macos-*`.

Список того, что доступно на вашей машине:

```sh
cmake --list-presets          # configure-пресеты
cmake --build --list-presets  # build-пресеты
ctest --list-presets          # test-пресеты
```

Авторитетная таблица пресетов (имя → хост → дерево сборки → примечания) —
в [CONTRIBUTING.md](../../../../../CONTRIBUTING.md#presets); здесь она не
дублируется.

## Требования

- **CMake ≥ 3.23** и компилятор **C++20**.
- **Ninja** для пресетов `clang-*`/`gcc-*`/`osxcross-*`/`macos-*` (они используют
  генератор `Ninja Multi-Config`). Пресеты `msvc-*` используют генератор Visual
  Studio и отдельный Ninja не требуют.
- Компилятор берётся из `PATH` по краткому имени (`clang`/`clang++`, `gcc`/`g++`,
  `cl` через генератор VS). CMake кэширует найденный путь при первой конфигурации —
  последующие изменения `PATH` не подменяют компилятор в существующем дереве.

Дополнительно по тулчейнам:

| Семейство пресетов | Требует |
|--------------------|---------|
| `msvc-*-2022` / `msvc-*-2026` | Visual Studio 2022 (v17) / 2026 (v18); ARM64-пресетам нужен компонент «C++ ARM64/ARM64EC build tools» |
| `clang-x86` / `gcc-x86` | 32-битный рантайм (`-m32`): `gcc-multilib`/`g++-multilib` на Linux; x86-окружение VS на Windows (см. Подводные камни) |
| `clang-arm64` / `gcc-arm64` | кросс-тулчейн aarch64; передайте `-DSCL_SYSROOT=<путь>`, если sysroot не является дефолтом компилятора. Только сборка. |
| `osxcross-*` | установленный [osxcross](https://github.com/tpoechtrager/osxcross) с `osxcross-conf` и инструментами `<triple>-clang` в `PATH`. Только сборка. |

## Пиннинг конкретной версии компилятора

Поставляемый пресет именует компилятор по семейству, не по версии. Чтобы
закрепить конкретную установку (GCC 12 против 13, конкретный Clang, …), добавьте
машинно-локальный `CMakeUserPresets.json` в корень репозитория, наследующий
поставляемый пресет — см.
[`project/cmake/CMakeUserPresets.json.example`](../../../../../project/cmake/CMakeUserPresets.json.example)
и раздел «Independent builds» в
[CONTRIBUTING.md](../../../../../CONTRIBUTING.md#presets).

## Подводные камни

Кусают независимо от IDE:

- **Windows `clang-x86`** — конфигурируйте и собирайте из **x86**-окружения Visual
  Studio (приглашение «x86 Native Tools», `vcvarsall.bat x86` или
  `Enter-VsDevShell -Arch x86`). Иначе линкер подтянет **x64**-CRT и упадёт с
  `machine type x64 conflicts with x86`.
- **MinGW `gcc` на Windows** — добавьте каталог `bin` вашего MinGW-w64 (standalone
  или тот, что поставляется с Qt под `Tools/mingw*/bin`) в `PATH` перед
  конфигурацией. `gcc-x86` требует multilib-MinGW; обычный 64-битный MinGW не
  удовлетворит `-m32`.
- **`osxcross-*`** — подгрузите окружение osxcross, чтобы `osxcross-conf` и
  инструменты `<triple>-clang` были в `PATH`; линкеру (`ld64`) могут также
  понадобиться его shared-библиотеки в `LD_LIBRARY_PATH`. Кросс-бинарники не
  запускаются на хосте сборки, поэтому test-пресета нет — только сборка.
- **Параллелизм** — пресеты `msvc-*` внедряют `/MP` (пофайловый параллелизм, через
  окружение пресета `CFLAGS`/`CXXFLAGS`, чтобы дефолтные MSVC-флаги CMake
  сохранились) и передают `/m` в MSBuild для параллелизма между проектами. `/m`
  доходит до MSBuild через `cmake --build --preset`; IDE, собирающая по каталогу,
  полагается только на `/MP`.
